# Безопасность iOS-клиента

Короткий обзор того, что защищено, где границы и что осознанно не делаем.

## Транспорт

- Только HTTPS, ATS без `NSAllowsArbitraryLoads` и без исключений доменов.
- **Certificate pinning** как в Android: SPKI SHA-256 промежуточного и
  корневого CA для `api-muzea.su`, `chat-muzea.su`, `auth.muzea.su`
  (`Muzea/Core/Networking/CertificatePin.swift`).
- Пины проверяются через `URLSessionDelegate`; несовпадение отменяет запрос.
- Пины на CA, а не на лист: листовые сертификаты меняются, CA — редко.
  При смене выпускающего CA пины нужно обновить синхронно с Android.
- `LinkPreviewService` ходит на произвольные сайты без пинов — это ожидаемо,
  но SSRF-защита включена (см. ниже).

## Токены и сессии

- access/refresh — только Keychain, `AfterFirstUnlockThisDeviceOnly`,
  не синхронизируются в iCloud.
- Refresh-токен одноразовый: single-flight `TokenRefresher`, повторный
  параллельный refresh не выполняется.
- Сеть/5xx при refresh **не** разлогинивают; сессия очищается только на
  400/401/403 от auth-service.
- При выходе/деактивации удаляются токены, chat-профиль, FCM-регистрация,
  кэши, черновики и outbox.
- Пароль не хранится: вход только по email-коду.

## Данные на устройстве

- Чаты, видео и GIF-список кэшируются в памяти; на диск попадают только
  исходящая очередь, вложения и диагностика.
- Файлы очередей/вложений/ошибок получают
  `NSFileProtectionCompleteUntilFirstUserAuthentication`.
- «Очистить кэш» не удаляет неотправленные сообщения и диагностику;
  выход/деактивация — удаляют.
- `URLCache` для API отключён: авторизованные ответы не оседают на диске.

## Внешние ссылки и OG-превью

- Ссылки `muzea://` и Universal Links ведут только на чат/новость/шаринг,
  доступ проверяется сервером по Bearer-токену.
- OG-превью: только http/https, блок localhost, `.local/.internal`,
  private/multicast IPv4, IPv6, IPv4-mapped IPv6; DNS-результат тоже
  проверяется; редиректы проходят ту же проверку.
- HTML читается потоково с лимитом 512 КБ; `og:image` с внутренним адресом
  отбрасывается.

## Диагностика

- `ErrorReporter` хранит до 5 МБ ошибок локально, отправляет при старте/входе
  пачками, удаляет только подтверждённые.
- Перед сохранением вычищаются почта, телефоны, Bearer/JWT и
  `token/password/secret/api_key`.
- Буфер очищается при выходе, чтобы ошибки не ушли под другим аккаунтом.
- Фатальные сигналы пишут только номер сигнала (без стека) — осознанный
  компромисс ради async-signal-safety.

## Приватность

- `PrivacyInfo.xcprivacy`: tracking = false, описаны собираемые данные
  (email, имя, userID, deviceID, фото/видео, сообщения, контакты, crash data)
  и required-reason API (UserDefaults).
- Разрешения камеры/микрофона/фото локализованы RU/EN.
- Рекламы и сторонней аналитики нет; Firebase используется только для FCM.

## Известные ограничения

- Нет E2E-шифрования: сообщения шифруются транспортом и защищены на сервере.
- Нет jailbreak/tamper detection.
- `AsyncImage` (аватары, публичные превью) использует системный URLSession
  без наших пинов — это не API-запросы с токеном; чувствительные вложения
  качаются через запиненный `HTTPClient`.
- Пиннинг CA ломается при смене CA; обновлять вместе с Android.
- Скриншоты в переключателе приложений не скрываются (как и в Android).
